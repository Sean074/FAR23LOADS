sloads — standard workflow commands (solo profile)
===================================================

Copy-paste command sequences for closing an issue / backlog item. This is a
crib sheet, not the rule: the authority is DEVELOPMENT_PROCESS.md (§0 solo
profile; §1-§9 with a second collaborator) and the closure tiers in CLAUDE.md.
If this sheet and those pages disagree, those pages win.

Two paths. Pick by what the change touches:

  PATH A  -- anything touching .py, a fixture, or config: branch -> PR ->
             squash-merge. CI runs before merge.
  PATH B  -- docs-only (every path *.md, docs/, or changes/): edit on main,
             close with solo_close.sh. No branch, guard-file gate only (~3 s).

Placeholders:  <N> issue number   <slug> kebab-case item name
               <type> fix|feat|note|docs   <Subject> commit subject in project
               style, e.g. "Short description (#N, tier M, YYYY-MM-DD)"


---------------------------------------------------------------------------
PATH A — code / behavior change (branch + PR)
---------------------------------------------------------------------------

# 0. Start clean, from an up-to-date main. Never branch off an old tip.
git checkout main
git pull

# 1. Open the branch (preflight: clean tree, on main; checks the issue is
#    open when <N> is given). Or plain: git checkout -b <type>/<N>-<slug>
scripts/solo_start.sh <N> <type>/<N>-<slug>

# 2. Do the work, AND land the closure artefacts on the same branch:
#      tier S: changes/<slug>.<type>.md fragment + delete the backlog row
#              (your own row only — no renumbering)
#      tier M: tier S + the affected PROGRAM_SPEC.md / standard-doc section
#              + a one-paragraph changes/<slug>.history.md fragment
#      tier L: tier M + theory_sources.md citation + full-format history
#              fragment; design note merged at AGREED before code
#    Closure travels in the PR — never in a follow-up.

# 3. Local gate, once, immediately before pushing (not after every edit).
#    While iterating, run only the module's own test file.
.venv/bin/ruff check sloads/ cli.py oracle.py app/ app_shell/ oracle_app/ scripts/
.venv/bin/mypy
.venv/bin/python -m pytest

# 4. Commit (one commit per closed item, project-style subject) and push.
git add -A
git commit -m "<Subject>"
git push -u origin <type>/<N>-<slug>

# 5. Open the PR. "Closes #N" in the body closes the issue on merge.
#    One open PR at a time.
gh pr create --fill --body "Closes #<N>"

# 6. Wait for the fast gate (test 3.12 uninstrumented, typecheck,
#    sbeam-roundtrip), then squash-merge. Auto-merge is not enabled on this
#    repo, so watch-then-merge:
gh pr checks --watch
gh pr merge --squash --delete-branch

# 7. Resync BEFORE starting anything else. A squash-merged branch is dead:
#    never commit to it again (its commits now conflict with their own
#    squashed copy on main — see DEVELOPMENT_PROCESS.md §0, #53/#54).
git checkout main
git pull

# 8. Post-merge check: the push to main runs the full matrix (3.9/3.11 +
#    coverage-instrumented 3.12). It is fixed forward — if it goes red,
#    the fix is the next item, not a revert.
gh run list --limit 3


---------------------------------------------------------------------------
PATH B — docs-only change (on main, no branch)
---------------------------------------------------------------------------

# Applies only when EVERY changed path is *.md, under docs/, or under
# changes/. Anything touching .py, a fixture, or config -> PATH A.

# 0. Up-to-date main, then edit in place.
git checkout main
git pull

# 1. Write the change + the tier-S fragment (changes/<slug>.<type>.md) and,
#    if closing a backlog row, delete that row.

# 2. Close. Gate scales to the guard files (~3 s), commits, lands --ff-only,
#    pushes; with <N> it also closes the issue with the main SHA.
#    --dry-run first shows the sequence without doing it.
scripts/solo_close.sh --slug <slug> "<Subject>"          # no issue
scripts/solo_close.sh --slug <slug> <N> "<Subject>"      # closing issue #N

# NOTE: solo_close.sh lands by pushing --ff-only to main. If branch
# protection currently requires a PR, that push is rejected — use PATH A
# even for docs, or lift the requirement first.


---------------------------------------------------------------------------
Recoveries
---------------------------------------------------------------------------

# Committed to a branch after its PR squash-merged (branch shows CONFLICTING):
# never hand-resolve — cherry-pick the residual commits onto a fresh branch.
git checkout main && git pull
git checkout -b <type>/<N>-<slug>-residual
git cherry-pick <sha1> <sha2>            # only the commits made post-merge
git diff <old-branch>                    # empty = tree identical, safe
# then PATH A from step 3; close the dead PR with: gh pr close <old-PR>

# solo_close.sh stops mid-sequence: it prints the recovery for the step it
# failed on — follow that, don't re-run blind.

# Gate failed on the branch: fix forward on the branch; the branch is the
# abort point (that is why code changes take one).
