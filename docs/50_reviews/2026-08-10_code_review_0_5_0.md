## 1. Findings — CRITICAL

### C1. SI mass-check deck `GRAV` acceleration is wrong by 25.4× — `sloads/export/mass_cards.py:403`

> **Closed 2026-08-10** with F-G2 (0.5.0 row 1). `units.DeliverableUnits.gravity`
> is now the single owner of the deck acceleration, drift-guarded per system,
> and the mass deck is solved in CI in both unit systems. This block no longer
> blocks the tag under RELEASE_PROCESS §3.2.
`g = u.force.factor / (u.mass.factor * u.length.factor)` is the
dimensional-consistency *identity* — it equals `G_IN_S2` = 386.0886 in **both**
unit systems (that equality is itself pinned by
`test_the_two_systems_agree_on_gravity_exactly`). It is g in in/s², always —
not g in deck units. The SI deck needs 9806.65 mm/s² and instead writes
`GRAV, …, 386.0886` under a header that says "386.0886 mm/s^2". Correct form:
`u.force.factor / u.mass.factor` (equivalently `G_IN_S2 * u.length.factor`).
Imperial (`length.factor = 1.0`) masks it completely.

**Consequence:** `--export-conm2 --units si` ships a mass-check deck whose
recovered inertia forces are 25.4× low — the artifact whose whole purpose is
the independent CONM2-vs-`inertia_only_cards` comparison "proves" sloads'
inertia wrong by a length factor. This is the D-19 failure class (parses
cleanly, silently wrong) the codebase organizes itself around preventing.
**Pinned:** no — the only GRAV assertion is that the string exists; magnitude
is asserted in neither system, and the mass deck is never solved in CI (F-G2).
